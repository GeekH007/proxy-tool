# V2.0 主界面「单代理 / 多代理」分离设计

日期：2026-10-25
状态：已实现（计划：docs/superpowers/plans/2026-10-25-single-multi-ui-split.md，7 任务全部完成，55/55 测试通过）

## 背景与意图

V2.0 引入多上游池后，主界面把「两格地址输入 + 池列表 + 分列状态行」全部混排：单代理用户用不上池管理，多代理用户的速率文本在一行里挤到折行（`up_status_label` wraplength=300），窗口高度随流量文本忽高忽低，池列表显示不全，添加上游交互也别扭。

**意图：预设分「单代理」「多代理」两种类型，界面形态跟随预设切换，两类场景互不干扰，同时根治换行/高度跳动/显示不全三个显示问题。**

## 已定决策（均经用户在 mockup 上确认）

1. **模式跟随预设**：每个预设自带类型（单/多），切换预设即切换界面形态，无手动模式开关。
2. **单代理形态**：V1 式「上游地址 + 端口」两格，下方状态框两行：开关状态行 + 一行速率（`↓ … ↑ … · N连`，永不换行）。
3. **多代理形态**：单行输入框 `IP:端口`，回车即入池（暂不做批量粘贴导入，将来可能加）。
4. **池表即状态表**：列 = 上游 | ↓ | ↑ | 连接 | 测试 | （移除按钮）。速率/连接数写进表格行，不再有独立的多上游状态行。
5. **测试结果进池表**：点「测试」逐台 generate_204，行内显示 `✓ 延迟` / `✗ 原因`；地址变更或测试中重复点击则旧结果作废。单代理形态测试结果显示在状态框里。
6. **新增预设弹窗**：点「新增」→ 小窗选类型（单代理 / 多代理）+ 名称 → 主界面进入对应形态的填写模式 → 填好保存；Esc 取消。
7. **迁移规则**：读旧配置（无类型字段）时按台数推断——1 台=单、≥2 台=多，推断后回写。

## 目标

- 单代理场景回到 V1 的简洁；多代理场景一屏看全每台上游的速率/连接/测试状态。
- 窗口高度只随「形态」和「池大小」变化，流量文本、测试结果不再撑动窗口。

## 非目标

- 类型互转（单→多、多→单）不做；想要另一种类型就新建预设。
- 批量粘贴导入上游（用户明确「先单行输入框」，留作将来）。
- 分流策略、入口/共享/SOCKS 网关的运行时行为一概不改。

## 反目标（做错了等于失败）

- 流量速率换行、窗口高度随流量文本跳动——必须根治。
- 单代理形态出现池列表或多余控件——不允许。
- 迁移破坏现有 3 个预设（默认[2台]、树莓派[1台]、91[1台]）的地址数据。

## 数据模型

- `presets[i]` 增加 `"type": "single" | "multi"`。
- `_normalize` 兼容：无 `type` 时按 `upstreams` 台数推断（1→single，≥2→multi）并回写。
- `single` 预设 `upstreams` 恒为 1 条；`multi` 至少 1 条（沿用现有「至少保留一台」约束）。

## 界面行为

### 单代理形态
- 「上游地址」「上游端口」两格直接编辑当前值（不是「添加」语义）；校验沿用现有 `_on_addr_changed`（红框、作废旧测试结果），失焦/回车生效并保存。
- 状态框：开关状态行 + 速率行（入口运行中 2 秒差分；与现行为同数据源，只是保证单行短文本不折行）。
- 无「移除」按钮（单代理不能删到 0 台）。

### 多代理形态
- 顶部单行「添加」框（placeholder 提示 `IP:端口`），回车/点添加入池，清空输入框；重复地址不重复加（沿用现有去重）。
- 池表：入口未运行时 ↓/↑/连接 列空白；运行中 2 秒差分刷新（数据源沿用 `_entry_status_text` 现有采样逻辑）。
- 每行「移除」，池剩 1 台时禁用（沿用现有约束）。
- 「测试」按钮在添加框旁；结果写池表「测试」列。

### 共用行为
- 切换预设、切换形态时窗口高度变化是预期行为（布局变化），流量刷新绝不改变高度。
- 共享上游跟随池[0]：单代理即该台，多代理即池[0]，行为不变。

## 迁移与兼容

- 配置文件无版本号则视为旧格式：推断 `type` 回写（见上）。
- 其余字段（`current`、`share`、`share_port` 等）不动。

## 不变的部分

- 入口 HttpServer、RelayServer、SOCKS5 网关、分流逻辑、注册表写法、托盘、开机自启、设置页、客户端列表窗。
- 「测试连通」逻辑本身（generate_204、超时、错误提示）不变，只是结果展示位置变化。

## 实现注意（项目已知坑）

- 工作线程禁调 `root.after`，WndProc 回调禁碰 tkinter，一律 queue + 主线程轮询（现有 `_ui_queue` 机制）。
- ttk.Label 没有 `fg` 别名，只能 `foreground`。
- 按钮文案不带省略号。
- Windows bat GBK/CRLF 相关脚本不改。

## 审查后补充决定（我的调用，可否决）

1. **新增模式的落盘语义**：正常态（编辑已有预设）回车添加上游=立即落盘（沿用现状）；「新增预设」填写模式=全部缓冲在内存，点保存才落盘，Esc 丢弃整个新预设（含已入池条目）——否则「取消」形同虚设。单代理新增模式同样缓冲。
2. **测试失败的显示**：错误不显示完整人话长文案，改为精简短词（`✗ 超时` / `✗ 连不上` / `✗ 拒绝` 等 2-4 字），池表列和单代理状态行都装得下；完整人话提示只在单代理状态框临时显示。不做悬停 tooltip（Treeview 无原生支持，工作量不成比例）。
3. **迁移边界**：判旧依据 = 预设无 `type` 字段（不引入 version 字段）；`type` 值非法按无 type 推断；`type="single"` 但实际 ≥2 台 → 改判 multi（绝不截断丢数据）；「推断后回写」= 打开只读不写盘，下次任何保存时顺带带上 `type`。
4. **单行解析规则**：按最后一个冒号 `rsplit(':', 1)` 拆地址/端口，无冒号 = 格式错误提示；IPv6 字面量维持现有校验拒绝（现有 `_valid_host_str` 本就拒绝，本次不动校验层，将来要支持是另一个任务）。
