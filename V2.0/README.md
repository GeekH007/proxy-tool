# 系统代理工具 V2.0（proxy_tool）

Windows 桌面小工具：把系统代理指向本机入口（`127.0.0.1:7890`），由一池上游代理透明接管——后台健康监测自动择优，一台故障秒切下一台，浏览器全程无感。支持多套预设、局域网共享（HTTP 转发 + SOCKS5 通道）、托盘常驻与开机自启。

单文件 `proxy_tool.py`，纯 Python 标准库（tkinter + ctypes 调 Win32），**零第三方依赖**，87 项单测。

**与 V1 的区别一句话**：V1 是"一个代理地址的开关"，V2 是"一池代理的调度器"——系统代理固定指向本机入口，上游挂了自动换、降级的殿后、恢复的自动归队；代价是工具不运行 = 全机断网。

## 功能

- **代理开关**：写注册表并广播生效，浏览器立即感知，无需重启、无需管理员权限；系统代理指向的是本机入口端口（默认 `7890`），不是上游本身
- **单代理 / 多代理两种预设**：预设自带类型，切换预设即切换界面形态——单代理是 V1 式「地址 + 端口」两格；多代理是一池上游（单行 `IP:端口` 回车入池）
- **池调度**（多代理预设）：健康优先选连接负载最少者，同负载轮询（拨号中的连接也计负载）；拨号失败顺延下一台，全挂才断客户端；首败只殿后不作首选，连败 3 次熔断 30 秒，熔断者仍是最后兜底
- **后台健康监测**：每台上游约 30 秒一次 HTTPS 探测（走代理 CONNECT + TLS 验证书、要求 204、双站点互为备份），连 3 败自动降级殿后、连 2 胜自动回归，无需人工干预；手动「测试连通」的结果有 30 秒保护期，不被后台立刻覆盖
- **上游管理**：备注名（≤16 字符）、停用/启用（至少保留一台启用）、双击行直接编辑；停用只影响新连接，已有连接继续传输
- **分列统计**：池表按上游分列显示备注/地址/下载/上传/连接/连通性；状态卡实时速率（2 秒差分）与总连接数
- **诊断日志**：有界异步 jsonl（滚动 2MB×3），白名单脱敏（不记目标地址、认证信息、异常原文），主窗「日志」按钮查看/导出 ZIP
- **局域网共享**：同 V1——HTTP 透明转发（默认 `7891`）+ SOCKS5 通道（默认 `7892`，可设用户名/密码），首次开启弹 UAC 一键放行防火墙；共享跟随池中第一台启用上游
- **托盘常驻 / 开机自启 / 单实例**：同 V1
- **V1 配置自动迁移**：首启读取 V1 配置（预设、共享端口/认证）迁走，之后两版本各守各的目录

## 运行环境

- Windows 10 / 11
- Python 3.8+（安装时勾选 *Add to PATH*）

## 快速开始

```bat
:: 方式一：双击
proxy_tool.bat

:: 方式二：命令行
pythonw proxy_tool.py
```

跑单测（87 项，无需网络）：

```bat
python tests\test_core.py
```

## 使用场景

**多上游择优**：有不止一台可用代理（如办公室出口 + 家里树莓派 + 租用节点）时，全配进一个多代理预设——工具自动选负载最轻的健康上游，某台挂了、慢了自动降级殿后，恢复了自动归队，浏览器和常用软件无感切换。

**局域网共享**：上游代理与手机不在同一网段时，同 V1——手机 Wi-Fi 代理手动填 `本机IP:7891`；不支持 HTTP 代理设置的应用（Telegram、VPN 型全局代理 App）把 SOCKS5 指向 `本机IP:7892`。

## 注意事项

- **工具未运行 = 全机断网**（系统代理指向它）；开机到自启就绪前有几秒断网窗口，属已接受代价
- 入口端口 `7890` 被 Clash 等占用时，在「设置」里改入口端口
- **V1 与 V2 不能同时运行**：共用同一单实例互斥体；且窗口标题不同，跨版本二次启动不会弹起对方窗口、只会静默退出
- 配置存于 `%APPDATA%\ProxyToolV2\`；V1 首启迁移一次后两边独立，勿再混用（V1 读不懂 V2 的 upstreams 格式，混用会被 V1 覆写成默认值）
- 与 V1「不产生日志文件」不同：V2 写脱敏诊断日志（滚动限量，含导出），不含配置、密码或请求内容
- 窗口标题（`系统代理工具 V2.0`）参与单实例定位，请勿修改 `APP_TITLE`

## 实现要点（给想改代码的人）

- 入口 = 透明转发，不解析协议（客户端发 CONNECT 或明文 GET 都原样转给选中的上游）；**入口只绑 127.0.0.1**——绑 0.0.0.0 等于给局域网开一条不经认证的通道
- 调度选择与占位同锁原子完成（token 幂等释放），并发连接读不到过时负载；失败节点的恢复探测单飞；代际隔离——切预设自增 generation，在途旧拨号的成败不写进新池
- 健康监测固定 2 线程领任务（无队列，不随上游数建线程）；stop/换代用 epoch 作废在途结果、不等待网络；监测线程从不碰 Tk，UI 更新全部走主线程 2 秒轮询
- 诊断日志队列满/锁竞争宁可丢诊断、绝不拖慢网络线程；`init_diagnostics` 仅在 `__main__` 显式启动，测试导入零副作用
- 转发层三入口共用：TCP_NODELAY + 256KB 收发缓冲、256 连接上限（满了即拒并留诊断事件）、拨上游 3 秒超时；SOCKS 握手共享 deadline 预算，隧道接通后 `settimeout(None)` 保 keep-alive 长连接
- 工作线程禁调 `root.after`，托盘 WndProc 回调禁碰 tkinter 对象，一律 queue + 主线程轮询（非线程安全 Tcl 构建）
- 托盘右键菜单用 Win32 原生 `TrackPopupMenu`——Tk 的 `tk_popup` 真实点击不派发选中，勿改回
- 真正退出只调 `root.quit()`：`root.destroy()` 不会终止 mainloop（进程残活），统一销毁放 `mainloop()` 之后
