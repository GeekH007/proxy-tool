## 一、目标与范围

**已实现：**

- 本机 HTTP 代理入口（透明转发、零协议解析），系统代理改指向它
- 上游池：健康优先选**连接负载最少**者，同负载轮询；拨号中的连接也计负载
- 故障切换：拨号失败顺延下一台，全挂才断客户端；分级降级 + 熔断
- 后台健康监测：每台约 30s 探一次 HTTPS，降级节点自动殿后、恢复后自动回归
- 上游池条目支持备注名与停用/启用；统计按上游分列
- 测试按钮逐台显式 CONNECT+TLS 探测，双站点互为备份
- 有界异步诊断日志（脱敏、可导出），故障可回溯

**非目标（维持不做）：**

- 局域网共享接池（共享跟随池中第一台启用上游，行为等价 V1）
- 单连接提速（多路分片下载）
- SOCKS5 上游（透明转发只认 HTTP 上游）

## 二、核心设计

### 2.1 入口 = 透明转发，不解析协议

客户端连上入口后无论发 CONNECT 还是明文 GET，字节原样转给选中的上游
（上游本来就是 HTTP 代理，什么都认识）。`HttpServer` ≈ RelayServer 克隆
+ 池选择器。**入口只绑 127.0.0.1**——绑 0.0.0.0 等于给局域网开一条
不经认证的通道（共享通道至少有 UAC 加规则的门槛）。

### 2.2 调度：负载感知 + 原子占位（UpstreamPool）

- **选择与占位同锁完成**（`acquire_attempt`/`release_attempt`，token 幂等释放），
  并发连接不会读到同一份过时负载
- **恢复探测单飞**：失败过的节点同一时刻只放一个连接去试（`begin_attempt`），
  探测成功前后续连接跳过它
- **代际隔离**：`set()` 自增 generation，切预设后在途旧拨号的成败不写进新池
- **分级降级**：首败降 1s（RETRY_SECS）不作首选；连败 ≥3 熔断 30s
  （BAN_AFTER/BAN_SECS）。降级只殿后、不封死——全部熔断时仍是最后的希望
- 共享切池用 `preserve_health=True`：地址没变时早退，不重置健康状态与探测间隔

### 2.3 后台健康监测（HealthMonitor）

- 固定 **2 个工作线程**直接领取到期节点，无任务队列，不随上游数建线程
- 每台约 **30s** 一次，与手动「测试连通」共用 `_probe_upstream`：
  显式走 HTTP 代理的 CONNECT + TLS，**验证书**、要求 204，不受系统代理干扰；
  双站点（Google/Gstatic generate_204）互为备份，6s 超时
- **五态机**：unknown → healthy / suspect → degraded → recovering；
  **连 3 败降级、连 2 胜恢复**。HTTPS 降级只是排序殿后——公共检测点异常时
  该上游仍能访问其他网站，兜底流量不封死（避免检测站点故障造成全断）
- 手动测试结果有 **30s 保护期**，不被后台结果立刻覆盖
- stop/换代不等待网络：epoch 作废在途结果；监测线程从不碰 Tk，
  UI 更新全部走主线程 2s 轮询（`_refresh_health_status`）

### 2.4 有界异步诊断日志（_DiagnosticLog）

- jsonl 滚动 2MB×3 份；**2048 深队列非阻塞投递**——队列满/锁竞争宁可丢诊断，
  绝不拖慢网络线程；日志线程独立，磁盘卡死不影响转发
- **白名单脱敏**：error 只保留类型词（timeout/refused/reset/…）与 errno/状态码，
  不记录目标地址、认证信息、异常原文；导出前再脱敏一遍
- `threading.excepthook` + `report_callback_exception` 双挂钩，线程/UI 异常均留痕
- 主窗「日志」按钮查看最近记录 / 导出 ZIP；`init_diagnostics` 仅在 `__main__`
  显式启动，测试导入零副作用

### 2.5 转发层调优（三入口共用）

- `_tune_sock`：TCP_NODELAY + 256KB 收发缓冲 + SO_KEEPALIVE
  （Windows 空闲 60s 起每 10s 探测，失联由 TCP 判定；**不给空闲长连接加读超时**）
- `_pipe_sockets`：`recv_into` 复用 64KB 缓冲；256KB 批量入账不逐块抢锁；
  单写者 progress 槽让 2s 快照能显示批次间的小流量，且与累计账不双算
- 每连接 **2 线程**（工作线程直接承担下行管道）
- 三入口共享 **256 连接上限**（BoundedSemaphore，满了即拒并计 `rejected_conns`
  + 诊断事件）；拨上游超时 3s；listen backlog 128
- SOCKS 握手共享 deadline 预算（慢速分包不能无限续期）、CONNECT 状态行严格
  解析；**隧道接通后 settimeout(None)**——keep-alive 空闲长连接不被拨号超时掐断

## 三、UI 与配置

- **卡片化布局**：灰 Shell + 白卡（状态卡/配置卡/共享卡）+ 页头（logo、
  版本徽章、设置、日志）+ footer（自启勾选、托盘提示）；窗口宽可调
- 状态卡三格指标：下载/上传速率（2s 差分）、当前连接数
- 池表列：备注 / 地址 / 下载 / 上传 / 连接 / 连通性；斑马纹、列宽按字体实测、
  纵向滚动条；行选中驱动「编辑」「停用/启用」按钮，双击行直接编辑
- **上游条目**：备注名（≤16 字符）+ enabled 标志（配置存 `upstream_options`，
  按 `ip:port` 键）；至少保留一台启用；编辑先存盘后热切、存盘失败回滚预设；
  停用仅影响新连接，已有连接继续传输
- 配置卡顶部常驻 HTTPS 健康汇总行（"2 正常 · 1 降级"）
- 「测试连通」+「详情」弹窗：逐台结果（含完整错误人话）+ 后台健康状态 + TCP 拨号连续失败数
- 专属 logo：`assets/` 四档 PNG（16/32/48/256，圆角外透明）；托盘
  `CreateIconFromResourceEx` 解 HICON（PNG 魔数校验、择近尺寸、系统图标兜底），
  窗口 `iconphoto` + 页头展示
- 托盘完整生命周期（`close()`：摘图标/DestroyWindow/UnregisterClass/DestroyIcon）；
  点 X 藏托盘常驻，托盘不可用才真退出（`quit_app` 与 `on_close` 分离）
- settings：`entry_port`（默认 7890）、共享/SOCKS 端口与认证（同 V1）
